# Checking the learning experience

The learning extension has automated checks for pixel arithmetic, borders, clipping, scaled kernels, valid parameter comparisons, cancellation, local progress and offline use. Those checks do not establish learning effectiveness.

Use this short session with beginner learners before expanding the feature set. No accounts or telemetry are needed. Record observations outside the app only with the participant’s consent.

1. Open **A noisy neighborhood**. Before changing a filter, ask the learner to predict how Gaussian and median blur will treat a single white pixel. Let them write the prediction in the optional guide.
2. Select Gaussian blur and use **Explain a pixel** on a noise dot. Ask which input intensities contribute most, how the weights combine, and why a border pixel reuses a mirrored neighbor. The explainer currently supports grayscale Box blur, Gaussian blur and Sharpen at preview kernels no larger than 7.
3. Compare kernels **3, 7 and 15**. Ask the learner to choose a setting and justify its effect on both noise and the square’s boundary. Applying a choice should feel reversible; ask them to undo it.
4. Compare Gaussian and Median at matching kernel sizes. Ask whether the original prediction changed, and have the learner record evidence in Reflect. Median has no weighted-sum explanation; treating it as convolution would be incorrect.
5. Try **Light is not even**, **Closing the gaps** or **A narrow range of light**. Ask for another prediction before showing a hint.

Look for whether the learner can explain the mechanism, distinguish observation from preference, recognize a tradeoff and connect the controls to Python. Note confusing language, controls they cannot find, and any assumption that a preview represents original-resolution pixels. Progress is learner-confirmed, not an assessment score.

The original synthetic fixtures are generated by `scripts/generate-learning-images.py`: a coordinate-hashed salt-and-pepper image, an uneven illumination pattern, a shape with known holes/split, and a narrow intensity ramp with a circular patch. Their bytes are deterministic and carry origin metadata. They are part of the production offline cache.

Learning notes stay in IndexedDB settings per project and lesson. Renaming preserves them; deleting a project removes them. Portable backups include the graph, lesson reference and original images, but not prediction/reflection notes or completion history. Existing schema-version-1 projects without a lesson reference still open normally.

Technical references: [OpenCV 4.13 Gaussian coefficient generation](https://github.com/opencv/opencv/blob/4.13.0/modules/imgproc/src/smooth.dispatch.cpp), [Setosa’s kernel teaching reference](https://setosa.io/ev/image-kernels/). OpenCV WebLab uses its own UI and fixtures.
